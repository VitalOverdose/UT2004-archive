Help Desk

Having a problem developing an Unreal Engine mod? Post your question here and we'll attempt to answer it.

Read Before Posting

A Wiki is not the ideal way to carry on long discussions. BeyondUnreal's [Unreal Development forums] are recommended instead.

Before Posting

The question that you plan on asking may have already be answered, either here or elsewhere. Before posting, please:

  • Scan this page
  • Search the Wiki
  • Search the [Unreal Development forums]

When Posting

When posting a question, please:

  • Use correct wiki markup
  • Give your question a heading (level 3)
  • Post your question above all other questions to avoid scrolling through older ones

After Posting

After you have received an answer to your question, please:

  • Write up the information somewhere on the site. This may involve refactoring the text from this page or a complete rewrite
  • Remove the question and answer from this page
  • Delete any images you uploaded to show the problem

If you see a question or discussion that has been idle for over three weeks, remove the question and answer.

Blue Ion: The deal is as simple as the question. I want to attach a karma actor to a mover so when it is triggered the karma actor would follow the mover and at the same time swing, be shot, and other fun stuff to do with karma actors.

Foxpaw: It is possible that you are not setting up the KBSJoint correctly. It is intended to go between either a Karma simulated actor and another Karma simulated actor, or a Karma simulated actor and the world.

I believe that attaching to a mover will require a modest amount of coding. However, if you are going to have to custom code something it might not make sense to use Karma at all, and instead code your own elevator physics, since it is a fairly simple case.

Alternatively, you could get rid of the mover and make the whole thing work on Karma. That would also require some amount of scripting.

Almost ready to launch mod, but a few questions

Kou: Okay, I'm about ready to release a demo of a mod I just made, but I (stupidly) designed the text in my windows based on pixels, and I'm running on 1280x1024 resolution. Is there a simple way to snap everything into place or am I going to have to set it for each resolution each time? This is an example of what I currently have...

       C.SetPos(550, 292);
       C.DrawColor.R = 255;
       C.DrawColor.G = 255;
       C.DrawColor.B = 255;
       C.DrawText( "Error!", False );

Foxpaw: The typical way to resolve this is to multiply by some value based on the resolution. Usually fractional numbers are used and they are multiplied by the resolution, but you can just as easily multiply by the resolution divided by 1280x1024.

IE:

local float XRes, YRes;

XRes = C.SizeX / 1280;
YRes = C.SizeY / 1024;

C.SetPos(550*XRes, 292*YRes);

Foxpaw: Personally I would gather the information by a collector actor, as you described above. This is fairly simple to implement and does not require subclassing all of the actors that you want to track. If you replace all of those with special "tracking" versions you will break most mutator functionality.

The biggest obstacle you will likely face is getting the information out. You could use a .ini file and save stuff into it, then have that file polled externally. However, it would probrably be better to use a "network" connection.

Though it's a bit hokey, you can set up a TCP or UDP server n Unrealscript server and connect to it with your program, then transfer the information across that connection. You can also make your server be the external application and have Unrealscript connect to it. Using a network protocol on the local machine is a bit iffy to me, but it has been demonstrated to be workable on other projects.

fataloverdoseHi,i was just looking through the pages on 'wUtils' and noticed that all the extra functions are extended off class Object. I didn't think you could go any higher than actor when it comes to adding any code. Or is it that you cant change any code but adding new classes is OK? Is that what the 'X' prefix on some packages is about?

Thanks.

Mychaeel: You can extend any class, including Object and other non-Actor-derived classes. The "X" prefix of some classes is only a somewhat poor (and obviously retrofitted) attempt by Digital Extremes to prevent clashes of their class names with engine class names.

fataloverdoseThanks. But as actor is not subclassed from 'wUtils' how is it i can use the functions if they are on a different branch of the class tree?

Mychaeel: They're all static functions, i.e. they promise not to access any instance variables or functions from their class and can thus be called on a class reference, not (just) an object reference. (The compiler enforces this promise.) So you call those methods as class'wUtilsClass'.static.method(), as described on wUtils.

Foxpaw: It sounds like the light is being blocked by something. When you build the lights it checks to see if the light can actually reach a destination before lighting it up.
